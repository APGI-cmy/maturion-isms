# Delegation and reporting to Maturion

Version: 1.1.0. Effective date: 2026-11-26.

Use `schemas/delegation.schema.json` and `schemas/result.schema.json`, together with the accepted adapter's authenticated dispatch/result contracts. Validate both structurally and semantically. The package must bind delegation ID, authenticated orchestrator, authority, tenant, user/role, project and current entity, allowed sources, expected outputs, constraints and current cumulative allowance. Identity text in JSON is not authentication. An approved AIMC adapter must supply a verified registration/permission receipt before execution.

Reject out-of-domain, unregistered or unauthorised requests with `REJECTED` and the reason `out_of_domain`, `invalid_authority` or `missing_inputs`; always return the delegation ID, failure `detail`, `recommended_action` and next responsible actor. An invalid-authority request must receive a minimal rejection audit receipt without reading course artifacts outside its authority. Never silently discard a task or obtain missing powers by requesting another specialist directly.

Return results to `maturion-agent` only. The envelope includes actual outputs and SHA256 evidence references, original tenant/user/project/entity, controller lineage, exact reviewed artifact and operative-QA receipt, blockers, cumulative usage, current QA decision and frozen components. The adapter must verify these bindings against its accepted delegation and stored receipts; a syntactically valid path/hash or model-supplied boolean is not verification. `SUCCESS` means only that the scoped delegated task succeeded. It does not mean the course is approved, published or accredited. `owner_review_ready` requires a complete artifact and all mandatory current QA passed; actual owner approval remains separate.

Maturion validates identity, source authority, scope, relevant QA and artifact bindings, uncertainty and tenant boundaries before synthesis. Missing evidence produces a blocked/partial result, never optimistic prose. The app should show real loading, completed-work and failure states. The two progress bars measure saved milestones and may progress at different rates; never animate invented AI progress or let bar completion substitute for a verdict.

The separately appointed adapter must durably record invocation and return receipts keyed by delegation ID. It must enforce the claimed authority and budget limits, not just document them. Replaying the same request returns its saved status; it cannot duplicate work, reset budgets or start another job. A different payload under the same ID is rejected. This bundle supplies interface contracts, not a live provider or controller adapter.

Commissioning must prove forged-authority rejection, cross-tenant/context swap rejection, changed same-ID input rejection, replay without duplicate execution, original counters surviving restart, invalid fifth-loop rejection and refusal of owner-ready when exact mandatory QA evidence is absent. Use isolated fixtures; leave live course jobs and LU2 unchanged. Maturion is the orchestrator; the governance specialist maps only through the accepted `course-creator-advisor` persona registration. No lateral invocation is permitted.
