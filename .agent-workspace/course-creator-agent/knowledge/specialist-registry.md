# Course Creator reporting registry

Version: 1.2.0. Effective date: 2026-11-26. Current authority: issue #2077.

| Identity layer | Identifier | Accepted scope source |
| --- | --- | --- |
| Canonical specialist | `course-creator-agent` | `governance/AGENT_REGISTRY.json` plus current contract/inventory identity |
| Reporting orchestrator | `maturion-agent` | Actual registered bounded runtime embodiment/induction proof; no invented ecosystem-wide capability |
| Generic AIMC persona/module | `course-creator-advisor` / `course-creator` | Accepted runtime route/provider/capability mapping |
| Course execution controller | Registered existing local controller | Original project/LU/entity/parent, sources, operations, QA, locks and budgets |
| Legacy ISMS persona | `course-crafter-advisor` | Unchanged historical/domain-specific persona, not silently broadened |

An identity or file existing is not active registration. The source candidate's empty governance-registry snapshot is preserved history, not the live registry or a requirement that the live registry remain empty. The current registry owner must record accepted target integrity and routing consistently, with a real registered Maturion parent.

Read-only private inspection/evaluation is a separately accepted capability. Full controller-scoped course creation requires the complete declared invocation/return paths and their evidence. The registry and runtime acceptance must display exactly that proved scope. Static prose, model replies or changing a status flag cannot manufacture missing production capability.

Maturion owns the user conversation, invokes the bounded specialist/controller capability and reviews/verifies its final evidence before synthesis. The existing controller owns producer, researcher and reviewer execution. The specialist cannot call another specialist directly, fork Maturion, modify the upstream Maturion contract, create a second controller or acquire CS2 powers.

Necessary Maturion Tier2 Course Creator entries are maintained in its specialist-registry, routing-rules and domain-flag-index under this issue. All unrelated historical entries and unavailable/stub capabilities retain their prior status; this adoption grants them no activation or routing authority.
