## What I Did

### Root Cause

The final step of `.github/workflows/producer-next-action-guidance.yml` ("Upsert sticky producer guidance comment") called `core.setFailed('ADVISORY_UNAVAILABLE: github_api_rate_limited\nINFRASTRUCTURE_RERUN_NEEDED: yes\nPR_DEFECT_INFERRED: no')` when its sticky-comment API calls hit the GitHub API rate limit. `core.setFailed` marks the entire job failed. This contradicted the workflow's stated contract from PR #1735 (commit c9612e2c) — "classify API rate-limit failures as advisory/infrastructure" — and contradicted the job's own design: the collection step degrades rate limits with warnings, the evaluate step emits an ADVISORY_UNAVAILABLE JSON result instead of failing, and the posted advisory comment itself renders `INFRASTRUCTURE_RERUN_NEEDED: yes / PR_DEFECT_INFERRED: no`. The `setFailed` was the single residual hard-fail path and fired on PR #2043's `ready_for_review` event.

### Files Modified

- `.github/workflows/producer-next-action-guidance.yml` — replaced `core.setFailed([...])` with `core.warning([...])` in the rate-limit catch branch of the final step, preserving the same three machine-readable classification lines.
